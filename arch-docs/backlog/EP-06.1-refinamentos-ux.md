# EP-06.1 — Correções e refinamentos de UX

**Status:** Concluída (verificação visual pendente) · **Alvo:** v0.1 · **Depende de:** EP-06

**Adendo pós-fechamento (mesmo dia):** uso real revelou que T04/T05/T07 precisavam de
mais — ver **EP-06.1-T10** abaixo.

Nota (fecho do épico): mesma limitação de EP-02/03/05/06 — sem `xvfb`/`sudo` neste
ambiente para abrir uma janela do Electron, então nenhum dos ícones, toasts, zebra
striping ou fluxos de path params/diretório padrão foi clicado de verdade nos dois
temas. `yarn lint`, `yarn typecheck` e `yarn test` passam (231 testes). Duas
divergências de escopo: (1) T05 não migrou o body multipart para `WKeyValueTable` —
a coluna de tipo text/file não existe na tabela genérica — em vez disso o campo de
valor ganhou o mesmo tratamento visual isoladamente; (2) T04 exigiu um campo novo no
formato de arquivo (`pathParams`, opcional, sem bump de versão — arch-docs/file-format.md
atualizado primeiro, conforme a regra).

Épico não planejado, aberto após uso real do app com dados de verdade
(collections, environments, respostas de API). Junta bugs concretos e gaps de
UX na mesma área de EP-06 (edição de request e environments) — não bloqueia
nem é bloqueado por EP-07..EP-11; pode ser intercalado com eles.

Achados e causas raiz (investigados no código antes de virar task):

- Trocar a aba de tipo de body reescreve o header `Content-Type` inteiro
  (nome, `enabled` e `description`), não só o valor — watcher em
  `RequestConfigTabs.vue`.
- A linha em branco sempre presente no fim de `WKeyValueTable` (params,
  headers, variáveis de environment, body urlencoded) vira linha real e
  persistida ao clicar no checkbox, mesmo sem nome/valor — parece "criar
  várias linhas vazias sem conseguir remover", mas o botão de remover já
  funciona; o bug é a recriação constante.
- Não existe distinção entre query params e path params (`:id` na URL é
  texto inerte).
- A árvore de collections só reflete o último estado salvo em disco — troca
  de método (ou qualquer campo) numa aba não some da árvore mesmo depois de
  salvar, porque `save()`/`saveActive()` não força um refresh da árvore.
- Não existe `@iconify/vue` nem componente de ícone — todo ícone hoje é SVG
  inline duplicado manualmente, e vários lugares (menu de contexto, empty
  states, botão de gerenciar environments) não têm ícone nenhum.
- Não existe sistema de toast/notificação — feedback de save/create/delete é
  ad hoc (banners inline, ou nenhum feedback).
- Não existe zebra striping em nenhuma tabela/lista.
- Não existe diretório padrão de workspaces — criar workspace sempre abre o
  diálogo de pasta do zero.
- Highlight/autocomplete de variável (EP-06-T05) não cobre a aba Docs, o
  editor de environments, nem body urlencoded/multipart.

### EP-06.1-T01 — Biblioteca de ícones (`@iconify/vue`)

**Status:** Concluída (verificação visual pendente) · **Tamanho:** M · **Depende de:** —

**Objetivo.** Ícones consistentes via `@iconify/vue` no lugar de SVG inline duplicado, e nos lugares que hoje não têm ícone nenhum.

**Escopo.**

- `@iconify/vue` em `dependencies`.
- `src/renderer/src/components/WIcon.vue`: wrapper sobre `<Icon>`, prop `name`, `class` repassada, `aria-hidden="true"` por padrão, tamanho via utilitário Tailwind (`size-3`/`size-3.5`/`size-4`).
- Substituir SVG inline duplicado por `WIcon` em: `WKeyValueTable.vue` (olho revelar, X remover), `RequestConfigTabs.vue` (X remover linha multipart), `RequestTabsBar.vue` (X fechar aba), `WSelect.vue` (chevron), `WTree.vue` (chevron expandir, triângulo de aviso).
- Adicionar ícone onde falta: botões "+Req"/"+Dir" da árvore, botão "Manage" de environments (`StatusBar.vue`), itens do `WContextMenu` (novo slot/prop de ícone em `ContextMenuItem`), todo uso de `WEmptyState` (slot `#icon` já existe no componente, nunca é passado).

**Critérios de aceite.**

- [x] Nenhum SVG duplicado manualmente restante nos componentes listados
- [x] Itens do `WContextMenu` (rename/duplicate/delete etc.) têm ícone
- [x] Todo `WEmptyState` do app passa um ícone
- [ ] `WIcon` verificado nos dois temas — pendente (sem `xvfb`/`sudo` neste ambiente, mesma limitação de EP-02/03/05/06)

**Fora de escopo.** trocar `WMethodBadge`/`WStatusBadge` de texto para ícone — mantém a regra do design system de texto colorido.

### EP-06.1-T10 — Highlight/autocomplete de verdade na URL e Params, path params travados na URL, contraste de tabela

**Status:** Concluída (verificação visual pendente) · **Tamanho:** M · **Depende de:** EP-06.1-T04, EP-06.1-T05

**Objetivo.** Corrigir três problemas de uso real reportados depois do fechamento do épico: (1) URL bar e o campo de valor de Params/Headers/env vars só tinham borda+tooltip agregados, não o highlight por `{{var}}` nem autocomplete via Ctrl+Space que já existiam no body; (2) a tabela de Path Variables permitia adicionar/remover linha manualmente, quando path params só deveriam existir enquanto o `:nome` correspondente está na URL; (3) texto das linhas de `WKeyValueTable` com contraste fraco.

**Escopo.**

- `WCodeEditor.vue`: modo `single-line` novo (`minimalSetup` em vez de `basicSetup`, sem quebra de linha — qualquer mudança que resultasse em mais de uma linha é descartada —, `Enter` emite `enter` em vez de inserir `\n`, `Ctrl+Space` funciona via `completionKeymap` explícito). Modo `bare` novo (sem borda/fundo próprios) para uso dentro de uma linha de tabela que já tem os dela.
- `RequestUrlBar.vue`: URL passa a ser um `WCodeEditor` de linha única (highlight real + autocomplete), no lugar do `WInput` com borda/tooltip agregados.
- `WKeyValueTable.vue`: campo de valor (quando não é secreto mascarado) passa a ser um `WCodeEditor` de linha única `bare`, com o mesmo highlight/autocomplete; nova prop `variableNames` propagada a partir de `RequestConfigTabs`/`EnvironmentEditorModal`.
- `WKeyValueTable.vue`: novas props `allowAdd`/`allowRemove`/`readonlyName` — a tabela de Path Variables em `RequestConfigTabs.vue` usa as três com valor travado (`false`/`false`/`true`), então uma linha de path param só aparece pela URL e o nome não é editável ali.
- `WKeyValueTable.vue`: removida a zebra striping introduzida em T07 (o `bg-stripe/5` deixava as linhas com aparência "desabilitada" quando combinado com texto fraco); nome/valor preenchidos ganham `font-medium` para mais contraste.
- Zebra striping revertida também em `WTree.vue` — feedback do usuário depois de ver a tabela: "deixe monocromática". Token `stripe` removido de `tailwind.config.js`/`main.css`/`arch-docs/design-system.md` — não sobra nenhum uso. `WTree`/`WKeyValueTable` voltam a ser monocromáticos (só hover/seleção mudam o fundo).
- `WKeyValueTable.vue`: nova prop `allowToggle` — `false` esconde o checkbox de habilitar. Path Variables usa `allow-toggle="false"`: um path param não tem estado "desabilitado" próprio, só existe ou não (controlado pela URL), então não faz sentido a linha ter um toggle que nada mais lê.
- `WCodeEditor.vue`: nova prop `highlightPathParams` — decora `:nome` na URL com cor própria (`method-patch`, sublinhado pontilhado), distinta de `{{var}}` resolvida/não resolvida. Só `RequestUrlBar.vue` liga.
- `WCodeEditor.vue`: `Enter` com autocomplete aberto agora deixa o `completionKeymap` aceitar a sugestão (`completionStatus(view.state) === "active"` devolve `false` do nosso handler) — antes o `Prec.highest` de `Enter` sempre vencia e o autocomplete nunca era aceito por teclado.
- `useVariablesStore`: novo `scopeSignal` (referência muda quando `environment.activePath`/`environment.items`/`workspace.tree` mudam). `useVariablePreview` passa a observar isso além de `[text, requestPath]` — editar uma variável ou trocar de environment agora re-resolve todo campo já visível na tela, em vez de deixar o destaque de "não resolvida" preso até o usuário digitar de novo naquele campo específico.

**Critérios de aceite.**

- [x] `{{var}}` na URL é destacado (resolvida/accent, não resolvida/status-4xx sublinhado) enquanto digita
- [x] `Ctrl+Space` na URL, e no campo de valor de Params/Headers/env vars, abre a lista de autocomplete de variáveis
- [x] `Enter` na URL dispara o envio, sem inserir quebra de linha
- [x] Colar texto multilinha na URL ou num campo de valor não quebra o campo em várias linhas
- [x] A tabela de Path Variables não tem linha em branco pra adicionar, nem botão de remover — só desaparece quando o `:nome` some da URL
- [x] Nome de um path param na tabela é texto, não input
- [x] Path Variables não tem checkbox de habilitar
- [x] `WTree` e `WKeyValueTable` não têm zebra striping
- [x] `:nome` na URL é destacado com cor própria, diferente de `{{var}}`
- [x] Selecionar uma sugestão de autocomplete com `Enter` a aceita, em vez de disparar o envio
- [x] Editar uma variável (ou trocar de environment) atualiza o destaque de "não resolvida" em todo campo já visível, sem precisar digitar de novo nele
- [x] `yarn lint`, `yarn typecheck`, `yarn test` (231 testes) e `yarn build` passam
- [ ] Contraste e alinhamento verificados nos dois temas — pendente (sem `xvfb`/`sudo` neste ambiente)

**Fora de escopo.** aplicar o mesmo editor de linha única no campo Name das tabelas (nome raramente contém `{{var}}`); aplicar em Description.
