# EP-09.1 — Produtividade de tabs/sidebar e ferramenta JWT

**Status:** Concluída (verificação visual pendente) · **Alvo:** v0.1 · **Depende de:** EP-09

Épico não planejado, aberto após uso real do app. Junta pedidos concretos de
produtividade nas abas de request e na árvore de collections com uma feature nova
(ferramenta de JWT) — não bloqueia nem é bloqueado por EP-10/EP-11; pode ser
intercalado com eles.

Achados e causas raiz (investigados no código antes de virar task):

- `RequestTabsBar.vue` não tem menu de contexto — só fechar uma aba por vez
  (`requestClose`/`forceClose` em `stores/requestTabs.ts`), sem "fechar todas"
  nem "fechar outras".
- A div de cada tab não tem largura fixa/mínima, só o título trunca em
  `max-w-40` — com muitas abas o scroll horizontal aparece e a largura de
  cada tab "pula" durante drag-reorder ou conforme o título muda.
- `WTree.vue`/`stores/tree.ts` só suportam seleção única
  (`selectedPath: ref<string | null>`) e arraste de um item por vez — não há
  `Set`/array de seleção em lugar nenhum.
- O menu de contexto da árvore (`WContextMenu` em `AppShell.vue`) já existe
  com Rename/Duplicate/Reveal/Delete, mas não tem Mover/Copiar, e não existe
  seletor de pasta/collection destino em lugar nenhum do app.
- `WCodeEditor.vue` sempre preenche 100% do container
  (`buildEditorTheme`, `height: "100%"`); quem trava a altura visível são
  wrappers `class="h-48"` em `RequestConfigTabs.vue`/`FolderConfigTabs.vue`
  (body JSON/raw, Docs) — não existe crescimento automático tipo textarea.
- Não existe nenhum código de JWT no repo (`grep` por "jwt" não retorna
  nada) nem lib de JWT nas dependências. Decode é JS puro (base64url +
  `TextDecoder`); encode/verify HS256 dá para fazer com a Web Crypto API do
  renderer (`crypto.subtle`), sem precisar de canal IPC novo nem de
  `node:crypto`.

### EP-09.1-T01 — Fechar todas / fechar outras abas

**Status:** Concluída · **Tamanho:** P · **Depende de:** —

**Objetivo.** Menu de contexto na barra de abas com "Fechar todas" e "Fechar outras".

**Escopo.**

- `RequestTabsBar.vue`: `@contextmenu` por tab, abrindo `WContextMenu.vue` (mesmo
  padrão já usado em `AppShell.vue`) com os itens "Fechar", "Fechar outras",
  "Fechar todas".
- `stores/requestTabs.ts`: novas actions `closeAll()`/`closeOthers(id)`, ao lado de
  `requestClose`/`forceClose` — reaproveitam o fluxo de confirmação existente para
  abas com alterações não salvas, encadeando uma confirmação por vez (nunca abrir
  vários modais ao mesmo tempo).

**Critérios de aceite.**

- [x] "Fechar outras" fecha todas as abas exceto a clicada
- [x] "Fechar todas" fecha todas as abas
- [x] Aba com alterações não salvas ainda pede confirmação individual antes de
      fechar, mesmo dentro de "fechar todas"/"fechar outras"
- [x] Cancelar uma confirmação no meio do processo interrompe o fechamento em lote
      sem fechar as abas restantes

### EP-09.1-T03 — Seleção múltipla com Ctrl+click na sidebar

**Status:** Concluída · **Tamanho:** G · **Depende de:** —

**Objetivo.** Selecionar mais de um item na árvore com Ctrl/Cmd+click e
arrastá-los juntos para outra pasta/collection.

**Escopo.**

- `stores/tree.ts`: novo estado `selectedPaths: Set<string>`, mantendo
  `selectedPath` existente como o item "ativo" dentro da seleção (compatibilidade
  com quem já lê `selectedPath`).
- `WTree.vue`, `onRowClick` (~linhas 201-208): tratar `event.ctrlKey`/`metaKey`
  para adicionar/remover da seleção, e `event.shiftKey` opcionalmente para range
  (se sair barato — senão fica de fora, ver Fora de escopo).
- `WTree.vue`, renderização (~linha 419): refletir todos os itens em
  `selectedPaths`, não só `selectedPath`.
- `WTree.vue`, `onRowPointerDown`/`onDragPointerUp` (~linhas 241-320): se o item
  arrastado faz parte da seleção múltipla, mover todos os itens selecionados
  juntos (múltiplos eventos `move`, ou um evento em lote novo) — do contrário,
  preservar 100% o comportamento atual de item único.

**Critérios de aceite.**

- [x] Ctrl/Cmd+click adiciona ou remove um item da seleção sem perder a seleção
      anterior
- [x] Click simples (sem Ctrl/Cmd) limpa a seleção múltipla e seleciona só o
      item clicado — comportamento hoje existente preservado
- [x] Arrastar qualquer item de uma seleção múltipla move todos os itens
      selecionados para o destino
- [x] Arrastar um item fora de uma seleção múltipla continua movendo só aquele
      item, como hoje

**Fora de escopo.** Shift+click para seleção em range, se o esforço de
implementação for maior que Ctrl+click sozinho — pode virar task própria depois.

### EP-09.1-T05 — Campos de texto com altura flexível (JSON, Docs, etc)

**Status:** Concluída · **Tamanho:** M · **Depende de:** —

**Objetivo.** Editores de body JSON/raw e Docs crescem com o conteúdo, como um
textarea, em vez de altura fixa com scroll interno.

**Escopo.**

- `WCodeEditor.vue`, `buildEditorTheme()` (~linhas 223-278): nova prop
  `autoGrow` — quando ativa, troca `height: "100%"` por `min-height` e deixa a
  altura seguir o conteúdo (`.cm-scroller` sem `overflow` forçado), com um teto
  opcional (`maxHeight`) para não crescer indefinidamente.
- `RequestConfigTabs.vue`/`FolderConfigTabs.vue`: trocar os wrappers
  `class="h-48"` do body JSON/raw e da aba Docs por `min-h-48` + `autoGrow` no
  `WCodeEditor` correspondente.

**Critérios de aceite.**

- [x] Colar um JSON grande no body faz o editor crescer verticalmente até o
      teto configurado, sem exigir scroll interno antes disso
- [x] Campo vazio ou com pouco conteúdo mantém a altura mínima atual (não
      encolhe abaixo do `h-48` de hoje)
- [x] Editores que não usam `autoGrow` (ex.: `ResponsePanel`, `AuthConfigEditor`,
      URL de linha única) continuam com o comportamento de altura fixa atual

### EP-09.1-T06 — Ferramenta JWT Decode/Encode

**Status:** Concluída · **Tamanho:** M · **Depende de:** —

**Objetivo.** Ferramenta standalone para decodificar um JWT (header + payload) e
para montar/assinar um novo JWT HS256, sem sair do app.

**Escopo.**

- Botão novo na toolbar (`AppShell.vue`) ou entrada no Command Palette, abrindo
  um `WModal` com abas "Decode" e "Encode".
- Aba Decode: campo de entrada (token colado) e saída de header/payload
  decodificados (base64url + `TextDecoder`, JS puro, sem depender de
  assinatura válida) usando `WCodeEditor.vue` para entrada e saída.
- Aba Encode: campos de header, payload e secret, gerando um JWT assinado em
  HS256 via `crypto.subtle` (Web Crypto API do renderer — não é `node:*`,
  não precisa de canal IPC novo).
- Sem canal IPC novo — toda a lógica roda no renderer.

**Critérios de aceite.**

- [x] Colar um JWT válido na aba Decode mostra header e payload como JSON
      formatado
- [x] Token malformado (não são 3 partes separadas por `.`, ou base64url
      inválido) mostra erro claro em vez de quebrar a tela
- [x] Preencher header/payload/secret na aba Encode gera um JWT HS256 válido
      (verificável decodificando de volta)
- [x] Trocar o secret muda a assinatura gerada

**Fora de escopo.** Algoritmos assimétricos (RS256/ES256 etc.) — só HS256 na
aba Encode; a aba Decode continua mostrando header/payload de qualquer
algoritmo, sem verificar assinatura.

**Notas de fechamento.** [[EP-09.1-T04]] precisou de um canal IPC novo não
previsto no escopo original — `node:copyInto` (`src/main/storage/tree.ts`,
`src/main/ipc/node.ts`, preload, `@shared`) — porque `duplicateNode` só
duplicava dentro da mesma pasta; "Copiar para..." precisa de um destino
arbitrário. Testado com fixtures reais em `tree.spec.ts` (request solto,
colisão de nome, pasta com filhos, guarda contra copiar para dentro de si
mesma). O algoritmo HS256 de [[EP-09.1-T06]] foi conferido contra o exemplo
padrão do jwt.io fora do app (Node com `crypto.subtle`), gerando o token
esperado byte a byte — mas, como o resto do app, não foi verificado numa
janela real (mesma pendência de verificação visual das notas em
[docs/backlog/README.md](README.md)).
